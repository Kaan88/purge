# ui: Purge desktop app

The WinUI 3 app. This tree is the stopgap UI imported from commit 0d9c008 by package M3-UI-IMPORT and pruned to the
M3 pages (docs/M3_DESIGN.md sections 7, 7a and 10). The later UI packages restyle the views, wire them to the
engine and the broker, and replace the hand-written DTOs. The custom `Main` starts `purge-engine --stdio` (next to
`Purge.exe`, or the file named by `PURGE_ENGINE`) in a kill-on-close job with two inherited pipes and sends
`engine.hello` and `programs.list` before XAML starts. `--sample` and `--bench-stub` use the sample-data stub
(`FakeEngineClient`) instead; so does a missing or failing engine, with a notice in the Programs page. The Uninstall
click starts the elevated broker on demand (never at app start); the sample stub keeps the button disabled. The
Uninstall pipeline hands its scan to the Leftovers page (M3-UI-S3), which sends `scan.candidates`,
`candidate.explain`, `plan.create`, `plan.execute` and `undo.run` over the same live broker link.

## Projects

- `Purge.App/`: the window (`Purge.exe`). Custom `Main` (`Program.cs`) starts the engine request before XAML init.
- `Purge.Client/`: `IEngineClient`, `Stdio/StdioEngineClient` (NDJSON JSON-RPC over the engine's stdin/stdout,
  `Stdio/EngineProcess` for the CreateProcessW + job launch), `EngineLink` (start-up with the fallback to sample
  data), `FakeEngineClient` (embedded sample JSON), hand-written DTOs in `Model/`, and `Cli/EngineDocs` (readers for
  the engine's JSON documents). `Broker/` holds the broker launcher, server check and NDJSON pipe client.
  `Pipeline/UninstallPipeline.cs` is the Uninstall page's view model (`UninstallController`) over the broker's
  `uninstall.prepare/run/observed` and `leftovers.scan` and the engine's `uninstall.route/run_user`; it holds no
  XAML, so `Purge.Client.Tests` drives every step against scripted links. `Rpc/` holds the engine API's DTOs
  (hand-written, source-generated by `System.Text.Json`) and `Schema/`/`Generated/` their committed JSON Schemas
  and generated glue: `cargo xtask gen-dto` writes them and `--check` fails on a difference.
- `Purge.Client.Tests/`: xunit tests and fixtures. `Cli/CliEngineClient.cs` (one engine process per verb, kill-on-close
  job, drain timeout) lives here as a test helper only; it is not a product link. `FixtureRoundTrip.cs` reads and
  writes every `crates/purge-rpc/fixtures/*.json` through the DTOs.

Stack: C# on .NET 10, WinUI 3, Windows App SDK 2.6.5 (component packages), unpackaged, self-contained, Native AOT,
x64, TFM `net10.0-windows10.0.19041.0`. Runs `asInvoker`; elevation goes through the broker.

## Build, test, run

Needs the .NET 10 SDK (10.0.4xx). For the AOT publish also Visual Studio Build Tools with the C++ desktop workload.

```powershell
# Debug build (JIT)
dotnet build ui\Purge.slnx
dotnet test ui\Purge.Client.Tests
ui\Purge.App\bin\Debug\net10.0-windows10.0.19041.0\win-x64\Purge.exe --sample

# Release: Native AOT, self-contained
dotnet publish ui\Purge.App -c Release -r win-x64 -o <out-dir>
<out-dir>\Purge.exe --sample
```

If the AOT link step fails with `'vswhere.exe' is not recognized`, put
`${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer` on `PATH` first.

Development switches:

| Switch | Effect |
|---|---|
| `--sample` | Sample data; the engine is not started. Without it the engine is started, and sample data stands in (with a notice) when it is missing or fails. |
| `--theme light` / `--theme dark` | Override the Windows theme for this run. |
| `--page <key>` | Open on `programs`, `queue`, `leftovers`, `history`, `vault` or `settings`. |
| `--bench-exit` | Close right after the first presented frame (launch bench). |
| `--bench-stub` | The stub engine answers `programs.list` with 300 rows after 20 ms (launch bench). |
| `--xaml-changes A,B` | Enable XAML optional changes, one at a time: `DefaultStyleOptimizations`, `IconNoGridOptimization`, `DeferContextFlyoutInit` (`OptimizeApplyStyles` is refused on 2.6.5). |

Launch markers (milliseconds since process creation): `module_init`, `main`, `engine_ready`, `list_reply`,
`on_launched`, `window_ctor`, `w_backdrop`, `w_icon`, `w_size`, `programs_enter`, `programs_xaml`,
`programs_ctor`, `rows_set`, `first_row`, `w_titlebar`, `first_tick`, `presented` (the title bar goes last in
the window constructor; `docs/M3_BENCH.md`, *Launch path*).
They show in Settings when present, and append one line per launch to the file named by `PURGE_BENCH_OUT`
(only that file turns them on). The bench itself is `docs/M3_BENCH.md`.

## Notes

- Under Native AOT, casting a `Style` or `Brush` looked up from code (`Resources["key"]`) throws
  `InvalidCastException`. Keep theme resources in XAML (`{ThemeResource}`) and toggle `Visibility`.
- Buttons whose content is not a plain string need `AutomationProperties.Name`.
- Anything given to `ItemsSource` must be a `List<T>` or `ObservableCollection<T>`, not a collection expression
  assigned to `IReadOnlyList<T>`.
- Under Native AOT, `ListView.ContainerFromIndex` returns a `ContentControl`; cast to `FrameworkElement`.
- A `LinearGradientBrush` with `SpreadMethod="Repeat"` corrupts rendering of the region.
- Never test with global keystrokes; drive the app through UI Automation and `--page`.
- Programs page (M3-UI-S1): tabs Apps, Components, Unnamed and Recent (AppX packages are apps, chipped "Store app"); rows
  start raw and take `programs.patch` (installer, MSI, Burn, AppX, system component, unnamed, parent key), `size.ready`,
  `icon.batch` (cache first, `IconLoader`, viewport first, placeholder tile on any failure) and `programs.get` (details pane) in place.
  The "removed outside Purge" group comes from `inventory.changes`, asked before `programs.list` because the engine stores the new list
  when a list ends. Uninstall starts the Uninstall pipeline (S2); Force remove, Modify and Remove entry are not offered.
  List rules are in `Purge.Client/Model/ProgramRules.cs`, tested in `ProgramsPageTests`.
- Uninstall pipeline (M3-UI-S2): the Uninstall click calls `MainWindow.OpenUninstall()` and starts
  `UninstallController`. It asks for the Windows prompt once (the first-elevation explanation comes first), starts
  `purge-broker.exe` elevated, and sends `uninstall.prepare`. A broker-route program runs `uninstall.run`; a
  medium-route one runs `uninstall.run_user` in the engine and then `uninstall.observed` in the broker. The confirm
  dialog shows the five steps, the exact command (the engine's for a medium route, the broker's frozen one otherwise)
  and its signer, the quiet toggle and the restore-point choice. After `leftovers.scan` the page hands
  `Shell/LeftoversRequest` to the leftovers page (`ILeftoversPage`, cached `LeftoversView`). Error bars: exit code with
  "Run forced cleanup" and Retry, still installed, restart needed (text only); the running-process line is a hint and
  "Check again", never a close control. `RestorePointMadeRow` shows only when a restore point was actually made (the
  uninstall step makes none; the cleanup plan does).
- Leftovers page (M3-UI-S3): eight groups in one virtualized `ListView` with header rows, group boxes that tick Safe
  items only, a weak-matches toggle, Protected and report-only sections, and a detail pane fed by `candidate.explain`.
  `plan.create`'s attention list is rendered from its own response (it can name absorbed ids that `scan.candidates`
  never pages). The waiting state shows the `consent.shown` code; the result page shows `plan.execute`'s counts, held
  items with their lockers and Undo all (`undo.run`). It never claims an item was moved before the result arrives, and
  a broker that ends mid-execute becomes "interrupted", not a result. It pages the scan S2 handed over without asking
  `leftovers.scan` again. Rules and tests are in `Views/Leftovers/LeftoversModel.cs` and `LeftoversPageTests`.
- Still sample-only or pending the UI packages: the Settings expanders not in the M3 list (running apps, start as
  administrator, packs, other profiles, AI), sample banners, badges on the rail, "Check for leftovers" (needs the broker).

All UI text is Purge's own. `cargo xtask ui-strings` checks every `*.cs` string literal and `*.xaml` attribute value of
12+ characters here (set `PURGE_UT_STRINGS` to the reference language file kept outside the repo).
